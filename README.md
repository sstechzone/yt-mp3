# ytmp3-api

A small FastAPI service that downloads an individual YouTube video and returns its audio as an MP3 file.

> Use this service only for content you own, have permission to download, or are otherwise legally entitled to access. You are responsible for complying with YouTube's terms and applicable copyright law. Do not expose a public, unauthenticated downloader.

## Features

- `GET /` service status
- `GET /health` health check for Render
- `GET /download?url=...` returns an MP3 attachment
- API key authentication through `X-API-Key`
- HTTPS-only YouTube URL allowlist
- Playlist downloads disabled
- Download size limit and socket timeout
- Concurrent-download limit
- Temporary job directory cleanup after response
- Docker image includes FFmpeg

## Requirements

- Docker (recommended), or Python 3.12+ and FFmpeg installed on your machine
- A YouTube URL you are authorized to download

## Run locally with Docker

1. Copy `.env.example` to `.env`.
2. Change `API_KEY` to a long, random secret. Do not use the example value.
3. Build the image:

   ```bash
   docker build -t ytmp3-api .
   ```

4. Run it:

   ```bash
   docker run --rm -p 8000:8000 --env-file .env ytmp3-api
   ```

5. Open `http://localhost:8000/docs` to view the API documentation.

## Run locally without Docker

Install FFmpeg first, then:

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
Copy-Item .env.example .env
# Edit .env and set API_KEY
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

Linux/macOS:

```bash
source .venv/bin/activate
cp .env.example .env
# Edit .env and set API_KEY
pip install -r requirements.txt
set -a && source .env && set +a
uvicorn app.main:app --reload --port 8000
```

## API usage

Health check:

```bash
curl http://localhost:8000/health
```

Download MP3:

```bash
curl -L \
  -H "X-API-Key: YOUR_SECRET_KEY" \
  --get \
  --data-urlencode "url=https://www.youtube.com/watch?v=VIDEO_ID" \
  http://localhost:8000/download \
  --output audio.mp3
```

The response is an `audio/mpeg` file attachment. The service currently accepts only HTTPS URLs on `youtube.com`, `www.youtube.com`, `m.youtube.com`, `music.youtube.com`, and `youtu.be`.

## Deploy to Render

1. Push this project to a GitHub repository.
2. In Render, choose **New + → Blueprint** and connect the repository.
3. Render detects `render.yaml` and creates the Docker web service.
4. `API_KEY` is generated by Render. Keep it private.
5. Wait for the deploy to finish, then test `https://YOUR-SERVICE.onrender.com/health`.
6. Send requests with the generated key in the `X-API-Key` header.

You can also create a Docker web service manually. Set the health check path to `/health` and add the environment variables listed below.

## Environment variables

| Variable | Default | Meaning |
|---|---:|---|
| `API_KEY` | `change-me` | Required secret; requests return 503 until changed |
| `MAX_FILE_SIZE_MB` | `100` | Maximum download/output size in MB |
| `SOCKET_TIMEOUT` | `20` | yt-dlp network socket timeout in seconds |
| `MAX_CONCURRENT_DOWNLOADS` | `2` | Simultaneous download jobs |
| `LOG_LEVEL` | `INFO` | Application log level |

## Run tests

```bash
pip install -r requirements.txt
pytest -q
```

The tests cover status routes, API-key enforcement, and URL validation. They do not make live YouTube requests.

## Important production notes

- Keep `API_KEY` secret. Rotate it if it is exposed.
- Use HTTPS and do not commit `.env` to GitHub.
- A socket timeout is not a strict total-job deadline. Large or slow media jobs may still take time; use a hosting platform with suitable request-duration limits.
- The configured maximum file size is enforced by yt-dlp and checked again on the resulting MP3. Actual behavior can vary by source and extractor.
- Temporary files are deleted after the response completes. If a process is forcibly terminated, its temporary job folder may remain; periodically clean the service's temporary directory if needed.
- Free hosting plans may sleep, have limited CPU/RAM, or impose request-duration and disk constraints.
- yt-dlp changes frequently because video platforms change. If downloads stop working, update yt-dlp and redeploy.
- This starter project is not a substitute for abuse monitoring, rate limiting by client/IP, or a production security review before offering the API publicly.


## Troubleshooting YouTube 422 errors

The API maps yt-dlp extraction/download failures to HTTP 422. The response is generic; inspect the terminal output from `docker run` or the Render service logs for the underlying yt-dlp message.

This image installs Deno and `yt-dlp-ejs`, components yt-dlp documents for full YouTube support. YouTube may still restrict particular videos, regions, IP addresses, or formats, and platform changes can require future yt-dlp updates.

After changing dependencies or Dockerfile, rebuild locally:

```powershell
docker build --no-cache -t ytmp3-api .
docker run --rm -p 8000:8000 --env-file .env ytmp3-api
```

For Render, push the changes to GitHub and trigger a new deploy.
